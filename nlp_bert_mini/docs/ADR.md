## NLP — BERT 기반 한국어 의미 검색 시스템 개발 및 성능 비교

### 의사결정 ① 활용 목적과 우선 평가 지표 선택 (CP-07~CP-09)

**문제**

검색 시스템의 활용 목적에 따라 첫 번째 검색 결과의 정확성, 상위 후보에 정답이 포함되는지, 정답 문서의 순위 중 무엇을 더 중요하게 평가할지 결정해야 합니다.

- **가정한 활용 상황(`USE_CASE`):** 사내 자료를 검색하면 다양한 부서에서 작성한 모든 관련 문서를 보여주는 기능
- **검토한 지표:** Hit@1, Recall@3, MRR@5
- **최종 우선 평가 지표(`PRIORITY_METRIC`):** MRR@5
- **선택 근거(사용자가 검색 결과를 어떻게 활용하는지):** 구글, 네이버같은 포털 검색 처럼 문서 하나만 보기보다는 관련도 높은순으로 5개를 보여주고 선택해서 볼수 있게 하는것이 사용자가 편할거라고 생각했습니다. 하나만 주고 없으면 결과가 아예 안나오는것보다 없다면 비슷한것이라도 보여주면 사용자가 능동적으로 사용할수 있기 때문입니다.
- **함께 고려할 다른 지표 또는 제약:** Recall@3, 상위 3개의 문서를 보고싶을수도 있습니다.

**분석 근거:** `02_nlp_model_analysis.md`의 2~4절

### 의사결정 ② 최종 검색 방식 선택 (CP-09)

**문제**

문자 기반 TF-IDF, 일반 BERT의 Mean Pooling, Sentence-BERT 검색 방식의 성능과 특성을 비교하여 최종 검색기를 선택해야 합니다.

- **비교한 선택지:** TF-IDF / BERT / Sentence-BERT
- **최종 선택한 검색 방식(`SELECTED_METHOD`):** tfidf (`tfidf`, `bert`, `sbert` 중 하나)
- **선택 근거(`SELECTION_REASON`, 실제 Validation 수치와 검색 실패 사례를 활용):** tfidf 가 단어 검색에 있어서는 mrr5이 0.9166666666666666 로 높았기때문입니다. 문맥 파악이 필요한 업무에서는 sbert가 나을거같습니다. 회사 게시판에 올라오는 악플 감지기능 처럼 거친표현은 없지만 내용이 나쁜 경우를 예로 들 수 있겠습니다.
- **트레이드오프(다른 방식과 비교해 얻은 장점과 감수한 단점):** 단어가 포함만 되어있으면 잘 찾을수 있다는 장점이 있고 단점은 단어가 포함되어있어도 내용이 다를경우를 구분하지 못해서 틀릴수 있다는 점 입니다. 그리고 질문에 있는 단어가 정답이 아닌 문서에 많이 있으면 그것으로 검색되는 단점이 있습니다.
- **추후 확인할 점(실제 사용 데이터, 검색 처리 비용 등):** Test에 사용되는 데이터의 양을 늘리고, 질문이 문서와 잘 매칭되게 입력이 되는지를 확인을 해야할 것 같습니다. 문서와 다른 단어로만 검색이 이루어진다면 다른 검색 방식을 고려해봐야 할 수도 있을것 같습니다.

**분석 근거:** `02_nlp_data_analysis.md`, `02_nlp_model_analysis.md`의 3~4절, `outputs/reports/cp09_selection.json`
